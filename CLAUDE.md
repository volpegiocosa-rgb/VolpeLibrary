# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

VolpeLibrary is the tooling and site for a home board-game catalog ("Libreria Volpe Giocosa"): a Python script that enriches the owner's game registry with data from BoardGameGeek (BGG), and a mobile-friendly search page that publishes the result. See `README.md` for step-by-step usage.

## Repository layout

- `legacy/` — the original static site and its source data. **Read-only**: nothing in this repo writes to `legacy/`; it is preserved for reference and as the input to `scripts/bgg_lookup.py`.
  - `Registro_giochi.xlsx` — the game registry the owner maintains by hand. Sheet `Tabella` has header row `Gioco | Posizione | Numero`; `Numero` is a derived helper column (numeric suffix extracted from `Posizione`, e.g. `Cubo 12` → `12`), not meaningful data — don't propagate it. This file is the source of truth for what games exist; `scripts/bgg_lookup.py` only reads it.
  - `game_library-1.js` / `catalogo.html` / `catalogo.php` — the original static page (title + shelf location only, client-side Levenshtein search). Superseded by `web/` but kept as-is.
  - `bgg_scraper_brute.py` — a different, out-of-scope script that enumerates BGG's entire ID range (~325k items) with a hardcoded token. Not used by anything here; gitignored because of the embedded token. Don't extend its full-catalog-scrape approach when working on `scripts/bgg_lookup.py` — the latter is scoped to the owner's own ~571 games via name search, not bulk enumeration.
  - `libreria-3.tgz` — page image assets.
  - `excel2js.m` — old Octave script that regenerated `game_library-1.js` from an earlier two-column version of the registry. Superseded by `scripts/bgg_lookup.py`.

- `scripts/bgg_lookup.py` — reads `legacy/Registro_giochi.xlsx`, looks up each game on BGG (search + thing endpoints), and writes an enriched catalog to `output/catalogo_bgg.json`. Key design points to preserve when editing:
  - `Gioco` and `Posizione` in the output are always the exact registry text (identity key for `--resume`); a separate `annotazioni` field holds text extracted from parentheses/quotes in the name; a small `CORREZIONI_NOME` dict fixes known typos *only* for the BGG search query, never for the displayed `Gioco`.
  - `--resume` treats the registry as the source of truth: on a full run (no `--limit`), records whose `Gioco`+`Posizione` no longer exist in the current registry are dropped (handles deletions/renames/moves); unchanged games are not re-fetched.
  - BGG's XML API2 requires an `Authorization: Bearer <token>` header (a 2025+ policy change — don't assume old unauthenticated examples work) and can respond `202` (still queuing) or `429` (rate limit); requests use jittered delays/backoff to avoid a robotic request pattern.

- `output/catalogo_bgg.json` — generated by the script above; not hand-edited.

- `web/` — the published front-end, reading `web/catalogo_bgg.json` (a copy of `output/catalogo_bgg.json` — re-copy after regenerating data). `catalogo.php` just sends no-cache headers and `readfile()`s `catalogo.html`, so there's one copy of the markup, not two like in `legacy/`. Deploy by uploading the whole folder's contents to the same directory on the host.

- `API_token.md` — gitignored; holds the real `BGG_API_TOKEN` value for local use.

## Data model notes

- Known data-quality quirks in the registry: a typo `"Linbreia alta 4"` and a trailing-space variant `"Cubo 30 "` in `Posizione`; a handful of duplicate `Gioco` titles at different `Posizione` (distinct physical copies — always key by `Gioco`+`Posizione` together, never `Gioco` alone).
- BGG fields added by enrichment: `bgg_id`, `giocatori_min`/`giocatori_max`, `durata_minuti`, `peso` (BGG "weight"/complexity, 1–5), `tipo` (BGG *subdomain* — Abstract/Strategy/Family/Party/Thematic/War/Children's/Customizable Game — read from `statistics/ratings/ranks/rank[@type=family]`, *not* the item's `type` XML attribute, which is just boardgame/expansion/accessory), `categorie`, `meccaniche`, `famiglie` (all lists), `bgg_errore` (null on success).
